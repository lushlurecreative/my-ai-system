# How to run a session (Shaun's one-page sheet)

1. **Open Claude Code in the project folder.** New session for every task. Never reuse yesterday's chat; the files remember, not the chat.
2. **Say what you want, in plain words.** Claude writes the task card itself and starts. There is no "go" to type: if you tell it to do something, it does it. It asks you a question only when only you can answer it and the answer changes the work.
3. **Let it work.** It can only touch the files its card lists. When it notices something broken on the way, it does not park it for you: it fixes it right after, proves it, gets it reviewed, and tells you afterwards (and writes one line in `docs/FIXED.md`). No permission pop-ups for normal work.
4. **It says "Done" only with evidence and after the reviewer agent passed it.** Otherwise the system bounces it back on its own.
5. **Initiative:** when a task is done and passed, Claude starts the next item that needs nothing from you, and when nothing is queued it walks the site as a customer and fixes what it finds. It never asks you to pick an order, never ends with a list of things to type, and never asks your OK to save, commit or push. Defects are fixed; new features, redesigns and anything about prices or customers go on your list. To switch the old "go" gate back on for a project, set `"requireGo": true` in `.claude/system.json`; to turn off the carry-on behavior, set `"initiative": false`.
6. **Protected files:** the task card is the approval, so you are never asked for an unlock word. When a task's card names a protected file (or the protected folder pattern) by its exact path under Allowed paths, Claude may change it, and every such edit is logged with file, task and time in `.claude/protected-edits.log` (a hook writes it; Claude cannot; read it any time to audit). A connector message (Lovable and similar) that mentions a protected word or file passes when the active card names it. The one exception is a protected database function (it changes the live database's own rules): Claude explains it in plain words and you type the one word it gives you, for example `unlock user_owns_deal`, or `override.txt` allows it. Hard blocks stay: force push, `rm -rf`, `git reset --hard`, database resets, DROP and destructive SQL, spending, credentials, deleting data, edits to CLAUDE.md, PROTECTED.md and `.claude/`, and no push to main before DONE with a reviewer PASS.
7. **Claude does the doing.** It runs the regression suite, runs deals, opens the browser and pages, checks mobile, runs tests and reads back deploys itself. It comes to you only for a password or login, money or a card, a decision, or a physical step, once, in one short message saying what it tried. **To reorder priorities:** say "move X to the top of NEXT.md". **To record a decision** ("park this", "disregard that", "from now on"): just say it. Claude adds one dated line to `docs/RULINGS.md` at once, and the startup screen shows it every session.

8. **Installing a tool or adding an agent:** Claude tells you what and why. You answer in chat: "yes, install posthog" or "yes, add agent marketing". Nothing happens without those words.
9. **Syncing your global tools library:** this needs a session on your own computer, because cloud sessions cannot see your files. Open Claude (the desktop app) in the my-ai-system folder and say "sync the global library." It reads the folder and changes nothing in it.

What never changes without you: the protected files, spending money, credentials, deleting data, CLAUDE.md, the hooks.

## Earning autopilot
Turn it on only after: the reviewer is grading every task, the "task A, also fix B" test refused B four times in a row, and a week of sessions with nothing you had to catch.
